FOCUSDUO — КОМПЛЕКТ ДЛЯ ДВУХ CODEX

Здесь готовые промпты, общий протокол и последний визуальный макет. Код приложения предстоит написать вашим Codex.

1. Создайте отдельный репозиторий/папку FocusDuo. Не используйте папку StudyMate.
2. Распакуйте комплект. Содержимое папки FocusDuo можно положить в корень нового проекта. Предпочтительно сделать один общий начальный коммит с docs/ до разделения веток.
3. Каждый работает в своём клоне на своём компьютере либо в отдельном worktree. Просто две ветки в одном рабочем каталоге не изолируют две одновременно работающие сессии.
4. Java-разработчик вставляет весь PROMPT_BACKEND_JAVA.txt в Codex в своём клоне; Kotlin-разработчик — весь PROMPT_DESKTOP_KOTLIN.txt в своём.
5. Другу нужен последний макет docs/design/focusduo-reference.png: он уже внутри комплекта. Если работаете без архива, приложите последнюю картинку к его сессии Codex. Путь /workspace/scratch из ChatGPT не переносит файл автоматически.
6. Оба промпта самостоятельные: одинаковый контракт встроен в каждый. Демо позволяет начать Kotlin UI до готовности Java.
7. Java-владелец отвечает за backend/ и общие корневые файлы; Kotlin-владелец меняет desktop/. У сборок отдельные wrappers.
8. Перед объединением передайте друг другу HANDOFF.md, проверьте фактическое совпадение контрактов и интеграцию. Общий контракт нельзя молча менять в одной ветке.
9. Для двух компьютеров оба клиента должны обращаться к ОДНОМУ серверу. 127.0.0.1 подходит лишь для сервера на том же компьютере. В общей сети укажите LAN-адрес машины с Java; для удалённой работы — доступный вам HTTPS/WSS-сервер.
10. Первый общий сценарий: регистрация двух пользователей -> одна комната -> 25-минутный раунд -> изменение задач -> пауза/продолжение -> восстановление клиента -> общий итог и история. Проверки времени в коде ускоряются внедряемыми часами.

Файлы examples в docs/contracts/fixtures — искусственные данные. Их токен не является рабочим секретом; они нужны для проверки одинаковых DTO.
Нативный Windows installer собирается и проверяется на Windows. Успешный Gradle exit на Linux сам по себе не доказывает наличие .exe/.msi.

В комплекте нет кода приложения и нет утверждения, что сервер, клиент или Windows-установщик уже реализованы.
