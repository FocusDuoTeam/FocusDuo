# Smoke-проверка запущенного сервера

`smoke.py` проверяет HTTP API уже работающего FocusDuo через Python 3.9+ и стандартную библиотеку. Дополнительные Python-пакеты не нужны. Python требуется только для этой проверки; приложение работает на Java 21.

Сначала запустите PostgreSQL и собранный JAR по [инструкции backend](../README.md). Затем из корня репозитория:

```powershell
py -3 backend/scripts/smoke.py
```

В bash/WSL/CI:

```bash
python3 backend/scripts/smoke.py --base-url http://127.0.0.1:8090 --wait-seconds 60
```

Скрипт ждёт готовности сервера по `401 UNAUTHORIZED` от `GET /api/v1/me`, затем проверяет:

1. Регистрацию двух пользователей, bearer-авторизацию и `/me`.
2. Create/join и восстановление текущей комнаты; повтор сохранённого запроса с тем же Idempotency-Key и отказ при изменённом теле.
3. FOCUS, создание и изменение задачи вторым участником; повтор изменения с исходной revision после нового изменения комнаты.
4. Pause/resume, сохранение `startedAt`, ручное завершение и фактическое активное время.
5. Одну общую запись истории и неизменность сохранённых целей/задач после последующего редактирования.
6. BREAK, закрытие комнаты вторым участником, освобождение членств, чтение закрытой комнаты и сохранение обоих результатов.
7. Logout обеих сессий и `401` для отозванных токенов.

`--base-url` — адрес сервера без `/api/v1`, query, пароля или токена. По умолчанию используется `http://127.0.0.1:8090`. `--wait-seconds` задаёт ожидание готовности (по умолчанию 60; 0 — одна попытка). Скрипт не запускает и не останавливает сервер или БД. Успех возвращает exit code 0, ошибка проверки — 1, неверные параметры — 2.

Каждый запуск создаёт **двух новых пользователей**, комнату и историю в выбранной БД. Имена имеют префикс `smoke_`; случайные пароли и токены существуют только в памяти и не выводятся. Используйте отдельное тестовое окружение: аккаунты и сохранённая история остаются в БД, поскольку контракт v1 не содержит удаления аккаунта/истории. Скрипт не очищает чужие данные. При ошибке он пытается закрыть текущую комнату своих аккаунтов и выполнить logout; при недоступной сети эта очистка не гарантируется и отмечается `WARN`.

Это проверка собранного приложения реальными HTTP-запросами, без управляемых часов. Она завершает раунды вручную и не ждёт реальных пяти минут. Raw WebSocket, истечение времени, гонки и восстановление после рестарта проверяются Maven integration tests; успешный HTTP smoke сам по себе не подтверждает эти сценарии или запуск Testcontainers.
