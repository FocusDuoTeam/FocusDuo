# Этапы backend и контрольные PR

Репозиторий: [KDvibers/FocusDuo](https://github.com/KDvibers/FocusDuo). Для каждого этапа: подготовить изменения и проверки → создать локальный коммит → **владелец выполняет push** → открыть PR → пройти review и проверки. PR не объединяется автоматически; решение о merge принимает владелец. Существующие изменения сохраняются, `desktop/` изменяет только Kotlin-разработчик.

## 1. Серверный MVP по контракту v1

Объём: весь реализованный Java backend — авторизация, комнаты на двоих, цели/задачи, таймер с паузой и перерывом, история, raw JSON WebSocket, идемпотентность, revision и транзакционные ограничения. Включает Flyway, Maven Wrapper, Compose, backend CI, необходимые тесты и документацию запуска/контракта.

Состояние: реализация и локальная проверка подготовлены к первому PR `feat/backend-mvp` → `main`. Выполнен `verify`: 40 тестов прошли с нативным PostgreSQL 17.11; Docker/Testcontainers и удалённый CI пока не запускались. [Описание PR](PR_STAGE_1.md) готово. Этап ещё не закрыт: впереди push владельца, создание PR, review и фиксация результатов проверок.

Контрольная точка: рассмотрен первый PR, проверены соответствие контракту и границы изменений; замечания и непройденные проверки явно зафиксированы. Решение о принятии PR остаётся за владельцем.

## 2. Проверка Docker/CI и воспроизводимого запуска

После review первого PR проверить чистый запуск PostgreSQL через Compose, стандартный Testcontainers-прогон `mvnw verify`, backend CI и команды запуска из документации. Добавить регрессионные проверки границ контракта и исправления по результатам review, не меняя согласованный протокол единолично.

Состояние: запланировано; успешный нативный PostgreSQL-прогон первого этапа не заменяет эти проверки. Изменения и результаты оформляются следующим локальным коммитом, затем владелец выполняет push и открывается отдельный PR.

Контрольная точка: в PR указаны фактически выполненные Docker/CI/launch-проверки и оставшиеся ограничения; рассмотрены исправления и регрессионные тесты.

## 3. Интеграция с Kotlin и итоговая передача

Согласовать подключение двух desktop-клиентов к одному серверу и пройти сценарий: register/login → create/join → FOCUS → правки задач → pause/resume → reconnect → finish/history → BREAK → close. Проверить обработку stale revision, повтор после потери ответа, `4401`, закрытого snapshot и восстановления состояния. Зафиксировать результаты приёмки и окончательные сведения в HANDOFF.

Состояние: совместный прогон с Kotlin ещё не выполнен. Независимо от готовности клиента можно готовить запросы, fixtures, серверные проверки и сценарий приёмки. Реализация и оформление `desktop/` остаются у друга.

Контрольная точка: отдельный PR с необходимыми backend-исправлениями и документированной приёмкой; локальный коммит → push владельца → PR/review/проверки. Непроверенные окружения перечисляются явно.

Исходные `PROMPT_BACKEND_JAVA.txt` и `PROMPT_DESKTOP_KOTLIN.txt` остаются локальными untracked-материалами и не входят в первый PR. Общий контракт и исходные fixtures сохраняются как согласованные материалы проекта.
