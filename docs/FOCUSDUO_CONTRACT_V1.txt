ОБЩИЙ КОНТРАКТ FOCUSDUO V1
Название продукта: FocusDuo. Этот блок одинаков для Java-сервера и Kotlin-клиента; считай его согласованным контрактом версии 1. Не меняй маршруты, JSON-поля, enum, единицы времени или правила единолично. При обнаружении реального противоречия опиши его и продолжай независимую работу. Если docs/FOCUSDUO_CONTRACT_V1.txt уже существует и отличается, сначала покажи различия; не перезаписывай файл.

ПРОДУКТ И АВТОРИЗАЦИЯ
Приватная комната на двух пользователей, общий рабочий раунд, отдельно запускаемый перерыв, личные цели и задачи, итог и история. Один пользователь состоит максимум в одной открытой комнате. Владелец управляет таймером и длительностями; каждый меняет только свои задачи и цель. Любой участник может явно закрыть комнату для обоих. Закрытие приложения, logout и потеря сети комнату не закрывают.
MVP: регистрация и вход по username/password. Сервер выдаёт непрозрачный случайный bearer-токен с expiresAt; это не JWT. В клиенте пароль и токен остаются только в памяти. После перезапуска пользователь входит снова; затем восстанавливается его текущая комната. Настройки могут сохранять адрес сервера и username, но не пароль/токен.
Username: 3–32 символа a-z, 0-9, underscore; нормализовать trim + lowercase. DisplayName: 2–40 символов после trim. Пароль: 10–128 символов, без trim/изменения регистра. Цель: 0–240 символов. Задача: 1–160 символов после trim, до 20 задач на участника. UUID передаются строками, даты — ISO 8601 UTC с Z, JSON — camelCase, длительности — целые числа. Focus: 300–10800 секунд, break: 60–3600 секунд; значения кратны 60. По умолчанию 1500/300.

ТРАНСПОРТ
Базовый адрес http://127.0.0.1:8090; REST /api/v1; raw JSON WebSocket /ws/rooms/{roomId}. Используй обычный WebSocket без STOMP/SockJS. Для REST и WebSocket-handshake: Authorization: Bearer <accessToken>. HTTP разрешён для локальной разработки; удалённое соединение настраивается через HTTPS/WSS. Секреты не помещать в URL, логи или репозиторий.
Все команды изменения комнаты возвращают HTTP 200 + RoomSnapshot. Все они требуют Idempotency-Key: UUID. Команды существующей комнаты также требуют X-Room-Revision: число; create/join освобождены от этого заголовка. GET, auth и history этих заголовков не требуют. Не вводить expectedRevision в JSON или If-Match.

МЕТОДЫ И ПУТИ (относительно /api/v1)
POST /auth/register {username, displayName, password} -> 201 AuthSession.
POST /auth/login {username, password} -> 200 AuthSession.
POST /auth/logout, без тела -> 204; отозвать текущий токен.
GET /me -> User.
GET /rooms/current -> {"room": RoomSnapshot или null}.
POST /rooms {focusDurationSeconds, breakDurationSeconds} -> RoomSnapshot.
POST /rooms/join {code} -> RoomSnapshot. Код trim + uppercase; повторный вход уже состоящего в этой комнате пользователя не занимает место.
GET /rooms/{roomId} -> RoomSnapshot.
PATCH /rooms/{roomId}/settings {focusDurationSeconds, breakDurationSeconds} -> RoomSnapshot; только владелец, вне RUNNING/PAUSED.
PATCH /rooms/{roomId}/me {goal} -> RoomSnapshot; своя цель.
POST /rooms/{roomId}/tasks {title} -> RoomSnapshot; своя новая задача, completed=false.
PATCH /rooms/{roomId}/tasks/{taskId} {title?, completed?} -> RoomSnapshot; хотя бы одно поле, только собственная задача.
DELETE /rooms/{roomId}/tasks/{taskId}, без тела -> RoomSnapshot; только собственная задача.
POST /rooms/{roomId}/rounds {kind:"FOCUS"|"BREAK"} -> RoomSnapshot; только владелец.
POST /rooms/{roomId}/rounds/{roundId}/pause, без тела -> RoomSnapshot.
POST /rooms/{roomId}/rounds/{roundId}/resume, без тела -> RoomSnapshot.
POST /rooms/{roomId}/rounds/{roundId}/finish, без тела -> RoomSnapshot.
POST /rooms/{roomId}/close, без тела -> RoomSnapshot; любой из двух участников, явное закрытие для обоих.
GET /history -> {"items":[HistoryItem,...]}; последние максимум 50 завершённых/отменённых раундов пользователя, endedAt DESC, roundId как дополнительный стабильный порядок. Без пагинации в v1.
GET /history/{roundId} -> HistoryItem; только участнику этого раунда.

ТОЧНЫЕ DTO
User = {id:UUID, username:string, displayName:string}
AuthSession = {user:User, accessToken:string, expiresAt:UTC-string}
Task = {id:UUID, title:string, completed:boolean}
Participant = {userId:UUID, displayName:string, goal:string, tasks:Task[]}
RoomSnapshot = {
  roomId:UUID, code:string, ownerId:UUID, status:"OPEN"|"CLOSED",
  revision:integer, serverNow:UTC-string,
  focusDurationSeconds:integer, breakDurationSeconds:integer,
  participants:Participant[], round:Round|null
}
Round = {
  id:UUID, kind:"FOCUS"|"BREAK",
  status:"RUNNING"|"PAUSED"|"COMPLETED"|"CANCELLED",
  durationSeconds:integer, startedAt:UTC-string, endsAt:UTC-string|null,
  remainingMs:integer, activeElapsedMs:integer, endedAt:UTC-string|null,
  completionReason:null|"ELAPSED"|"MANUAL"|"ROOM_CLOSED"
}
HistoryParticipant = {
  userId:UUID, displayName:string, goal:string, tasks:Task[],
  totalTaskCount:integer, completedTaskCount:integer
}
HistoryItem = {
  roundId:UUID, roomId:UUID, kind:"FOCUS"|"BREAK",
  status:"COMPLETED"|"CANCELLED",
  completionReason:"ELAPSED"|"MANUAL"|"ROOM_CLOSED",
  durationSeconds:integer, startedAt:UTC-string, endedAt:UTC-string,
  activeElapsedMs:integer, participants:HistoryParticipant[]
}
Ошибка всегда = {
  code:string, message:string, requestId:string,
  fieldErrors:object, snapshot:RoomSnapshot|null
}
fieldErrors — объект fieldName -> текст ошибки, пустой при отсутствии ошибок полей. snapshot заполняется при REVISION_CONFLICT только для авторизованного участника; в остальных случаях null.
Коды: 400 VALIDATION_ERROR; 401 UNAUTHORIZED; 403 FORBIDDEN; 404 NOT_FOUND; 409 USERNAME_TAKEN, ROOM_FULL, ALREADY_IN_ROOM, ROOM_CLOSED, INVALID_STATE, ROUND_NOT_CURRENT, REVISION_CONFLICT, IDEMPOTENCY_KEY_REUSED; 500 INTERNAL_ERROR. Не показывать клиенту stack trace. Неавторизованный WebSocket-handshake отклонить; уже открытый сокет при истечении/отзыве токена закрыть с кодом 4401.

СОСТОЯНИЕ И ТАЙМЕР
1. Новый OPEN room содержит владельца, пустые цель/задачи и round=null; revision начинается с 1. Второй участник присоединяется по коду. Код — непрозрачная для клиента строка; сервер генерирует FD- плюс 6 случайных непохожих букв/цифр. Клиент не хардкодит длину, формат и код с картинки.
2. FOCUS можно начать только владельцу, при двух участниках и отсутствии RUNNING/PAUSED. BREAK запускается вручную, только если текущий последний раунд — COMPLETED FOCUS. Одновременно один активный раунд. pause разрешён из RUNNING, resume — из PAUSED, finish — из RUNNING/PAUSED; иначе INVALID_STATE. Каждая команда pause/resume/finish адресует конкретный текущий roundId; несовпадение даёт ROUND_NOT_CURRENT.
3. RUNNING: endsAt — срок окончания; remainingMs и activeElapsedMs вычислены на serverNow. PAUSED: endsAt=null, остаток и активное время заморожены. startedAt не меняется при resume.
4. COMPLETED/CANCELLED: endsAt=null, remainingMs=0, endedAt заполнен. activeElapsedMs сохраняет реальное активное время без пауз; при досрочном завершении оно меньше durationSeconds*1000. Нельзя вычислять его как полную длительность из terminal remainingMs=0.
5. Автоматическое завершение: COMPLETED/ELAPSED, endedAt равно сроку окончания даже при поздней обработке. finish: COMPLETED/MANUAL и фактически прошедшее активное время. close: RUNNING/PAUSED становится CANCELLED/ROOM_CLOSED; уже завершённый раунд не переписывается. История фиксируется один раз по roundId.
6. На close статус комнаты CLOSED, активные членства обоих освобождаются, закрытый снимок рассылается обоим. Состав закрытой комнаты и история сохраняются; прежние участники могут читать закрытый снимок. Новые изменения CLOSED запрещены. Отдельного leave/смены партнёра в v1 нет.
7. Цели/задачи комнаты сохраняются между раундами до явного редактирования. В истории находится неизменяемая копия на момент завершения/отмены; последующие изменения её не затрагивают. BREAK хранится с отдельным kind. Досрочный результат и отмена имеют явные подписи; отмена не считается успешно завершённым фокусом.
8. Сервер — источник истины. Хранить состояние в PostgreSQL и восстанавливать после рестарта. Просроченный RUNNING актуализировать одним общим транзакционным методом при фоновом обходе и чтении/команде. Сначала актуализация срока, затем проверка версии и допустимости новой команды. Автоматическое завершение, его история и revision должны зафиксироваться, даже если последующая команда получает 409; возвращаемый snapshot соответствует зафиксированным данным, а не откатившейся транзакции.
9. Изменения комнаты/её задач/раунда увеличивают revision; секундный отсчёт не увеличивает её. При одинаковой revision значения serverNow и вычисленных временных полей могут обновляться. Транзакции сериализуют изменения одной комнаты; ограничения БД защищают вместимость и одно активное членство.
10. После аутентификации проверять сохранённый Idempotency-Key пользователя ДО повторного применения бизнес-правил/проверки revision. Повтор того же method/path/body/исходной revision возвращает сохранённый результат без второго изменения. Другой запрос с тем же ключом -> IDEMPOTENCY_KEY_REUSED. Уникальность (userId, key) гарантирует БД. При двух одновременных одинаковых запросах один выполняется, второй после фиксации получает тот же результат без ложного конфликта версии. Успешный результат ключа и изменение данных сохраняются одной транзакцией. Replay может содержать более старый снимок; клиент применяет правила revision.
11. При REVISION_CONFLICT вернуть 409 с актуальным snapshot. Клиент применяет снимок и предлагает повторить действие; новое действие получает новый ключ. Не повторять команду бездумно с новой revision. При неоднозначном сетевом сбое можно повторить только тот же запрос с тем же ключом и исходной revision.
12. Первое сообщение после WebSocket-подключения и каждое изменение:
{"type":"ROOM_SNAPSHOT","data":RoomSnapshot}
Передавать полный снимок после commit. Между подпиской и начальным чтением не должно теряться изменение: зарегистрировать подписку до чтения первого snapshot либо применить эквивалентную согласованную синхронизацию. Секундные тики сервер не рассылает. Серверные ping/клиентские pong — стандартные WebSocket control frames, не отдельный JSON-протокол.
13. Клиент сравнивает revision только в пределах roomId: меньшие версии игнорирует; при равных не откатывает данные, более свежий serverNow может уточнить часы. Поздние сообщения предыдущего соединения/комнаты игнорируются. После reconnect нужен новый полный snapshot до разрешения изменяющих действий.
14. Отображаемый отсчёт привязать к serverNow/endsAt и монотонным локальным часам, по возможности учитывая задержку сети. При пробуждении ПК и восстановлении сети синхронизировать заново. Достижение нуля в UI не создаёт историю и не объявляет серверное завершение.
15. Локальный статус соединения основан на реальной сети. Статус «В фокусе» отражает активный раунд; протокол v1 не измеряет внимание пользователя и не сообщает отдельное online-присутствие друга.
