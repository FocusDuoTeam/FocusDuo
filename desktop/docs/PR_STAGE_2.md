
## Описание

Добавляет рабочую локальную комнату по светло-зелёному макету. После создания пользователь видит ожидание второго участника и может подготовить цель и задачи; явные инструменты демо позволяют добавить партнёра и проверить комнату от имени каждого участника. Все изменения находятся в `desktop/`.

- Модели состояния, `FocusDuoRepository`, `FakeRepository` и `StateFlow`; последовательные изменения и неизменяемые снимки с revision.
- Главная, создание комнаты, вход в заполненный пример по коду и возврат к текущей комнате.
- Круговой индикатор настроенной длительности, участники, роль создателя, собственная и чужая карточки задач, счётчики из состояния.
- Редактирование цели, добавление/изменение/отметка/удаление своих задач; валидация длины и лимита 20 задач, защита чужих задач в интерфейсе и репозитории.
- Копирование кода и диалог приглашения, изменение длительностей только владельцем, формы ошибок и подтверждения.
- Явные демосценарии присоединения партнёра, смены точки зрения и сброса, без сетевых запросов или автоматического включения fake.
- Обновлённые README, план этапов и HANDOFF.

### Проверки

- Windows / JDK 21: `gradlew.bat test --console=plain` — **17 passed, 0 failures, 0 errors, 0 skipped**: 12 тестов репозитория и 5 тестов запуска. Проверены права, CRUD, валидация, членство, конкурентный лимит задач, неизменяемость снимков, настройки, профиль и сброс.
- Реальный Compose-интерфейс запущен через `run.ps1 -Demo` в размерах 1280×800 и 1000×700. Проверены ожидание → два участника, права разных пользователей, длительность, полный цикл задачи, ошибки, длинный русский текст, прокрутка, Tab/Enter/Escape и копирование кода через системный clipboard.
- Сохранены [шесть реальных скриншотов и подробные результаты QA](HANDOFF.md#визуальная-проверка), включая [комнату](screenshots/stage-2-room-1280x800.png), [ожидание](screenshots/stage-2-waiting-1000x700.png) и [ошибку формы](screenshots/stage-2-task-validation.png).

Минимальное окно 840×600 и полный аудит доступности отдельно не проверялись; живая интеграция с backend в этот этап не входила.

### Границы этапа

Второй участник моделируется в памяти одного приложения. Круговой таймер пока показывает настроенную длительность; отсчёт, управление раундами, BREAK, закрытие комнаты и итог идут следующим этапом. История, авторизация, `RealRepository`, REST/WS, интеграция с Java и Windows-установщик ещё не реализованы. Серверный контракт и backend не изменены.
