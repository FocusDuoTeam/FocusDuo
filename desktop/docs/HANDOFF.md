# FocusDuo Desktop — текущая передача

## Статус на 10 октября 2026

**Этап 2 из 10 завершён:** `FakeRepository`, комната, участники, цели и задачи. Следующий этап — локальная симуляция таймера и итог раунда. [План всей desktop-части](ROADMAP.md) разбит на небольшие этапы; следующий этап не выполняется автоматически в том же заходе.

## Что реализовано

- Самостоятельная desktop-сборка: Kotlin/JVM 2.2.20, Compose Desktop 1.9.1, Gradle Wrapper 8.13 с SHA-256 и Java toolchain 21. PowerShell-скрипт находит JDK 21 без изменения постоянных системных настроек.
- Светло-зелёные компоненты Compose, Manrope с кириллицей, согласованные Canvas-иконки, системная рамка Windows.
- Явное включение демо через `--demo` или стартовый экран. В заголовке окна и интерфейсе видна пометка режима; серверные соединения не создаются.
- Модели комнаты и задач, интерфейс `FocusDuoRepository`, локальный `FakeRepository` и `StateFlow`. Изменения сериализуются через `Mutex`, снимки сохраняют неизменяемые списки и `revision`.
- Главная с созданием пустой комнаты, входом по коду и переходом к текущей комнате. Новая комната содержит владельца, пустую цель/задачи, `round=null` и `revision=1`.
- Подготовленный пример `FD-DEMO42`: два участника с целями и задачами; локальный пользователь присоединяется как обычный участник, владельцем остаётся друг. Регистр кода и пробелы по краям нормализуются, неизвестный код показывает ошибку.
- Комната по светлому макету: круговой индикатор слева, карточки участников под ним, собственные и чужие задачи справа. Код, состав комнаты, цели, счётчики и длительность поступают из состояния.
- Собственная цель до 240 символов; добавление, редактирование, отметка и удаление собственных задач. Название после trim содержит 1–160 символов; максимум 20 задач на участника. Чужие задачи доступны только для чтения, в том числе владельцу комнаты.
- Копирование кода в системный буфер обмена и диалог приглашения без внешних отправок. Изменение длительности владельцем: фокус 5–180, перерыв 1–60 целых минут.
- Отдельный блок управления демо: симуляция присоединения друга, переключение взгляда между участниками и сброс с подтверждением. Переключение не меняет владельца; собственная карточка определяется по ID текущего пользователя.
- Локальное изменение имени 2–40 символов, формы ошибок, подтверждение удаления задачи, отмена ввода. Переход между главной и комнатой сохраняет текущую локальную сессию.

Прежняя форма имени/цели с предпросмотром этапа 1 заменена действиями в приложении: имя меняется в боковой панели, цель — в собственной карточке комнаты. Инструменты демо расположены под комнатой и доступны прокруткой.

## Решения и границы

Рабочая ветка — `feat/desktop-mvp`, обновлена до `origin/main` с merge-коммитом `a508020`: в нём уже объединены предыдущий desktop PR #3 и backend PR #2. Изменения этого этапа находятся только внутри `desktop/**`; backend и общие файлы не менялись. Выполнено только локальное fast-forward обновление из origin/main. Новые коммиты и удалённые push/merge/publish агентом не выполнялись.

Окончательный дизайн — [последний светло-зелёный макет пользователя](design/light-green-reference.png). Он заменяет тёмную тему из исходного ТЗ и общих `docs/design/`; контракт V1 сохраняется. Справочные копии полного ТЗ и контракта находятся в `desktop/docs/reference/`.

Смена пользователя, заполненный пример, редактирование имени и сброс являются инструментами демо, а не расширением API. Сброс не выдаётся за серверные `leave`/`close`. Демо не показывает сетевой online-статус или измерение внимания партнёра.

Из корня репозитория, PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\desktop\run.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\desktop\run.ps1 -Demo
powershell -NoProfile -ExecutionPolicy Bypass -File .\desktop\run.ps1 -Demo -Width 1000 -Height 700
```

Тесты из `desktop/` с `JAVA_HOME`, указывающим на JDK 21:

```powershell
.\gradlew.bat test --console=plain
```

Финальный прогон `gradlew.bat test --console=plain` завершился **BUILD SUCCESSFUL за 2 секунды: 17 тестов, 0 failures, 0 errors, 0 skipped**. Результат подтверждён XML: 12 тестов `FakeRepositoryTest` и 5 `LaunchOptionsTest`. Отчёт: `desktop/build/reports/tests/test/index.html`; XML — `desktop/build/test-results/test/`.

К пяти тестам запуска добавлены сценарии `FakeRepository`: пустая новая комната, нормализация и повтор входа, ошибки членства, вместимость и смена точки зрения, CRUD и права, длины и атомарность неуспешных команд, цели, конкурентный лимит 20 задач, настройки владельца, неизменяемость снимков, профиль и сброс. Проверка использовала JDK 21 на Windows. Команды `run.ps1 -Demo` и `run.ps1 -Demo -Width 1000 -Height 700` действительно запускались.

## Точные ограничения

1. Демо хранится только в памяти одного процесса. Перезапуск удаляет комнату и задачи; второй участник моделируется локально. Работа двух реальных клиентов ещё не реализована.
2. Круговой таймер показывает настроенную длительность без отсчёта. Запуск, пауза, продолжение, завершение, BREAK, закрытие комнаты и итог относятся к этапу 3; недоступные действия обозначены в интерфейсе.
3. Нет истории, настоящих форм входа/регистрации и общих настроек сервера. Изменение имени в демо не является серверным редактированием профиля.
4. Нет `RealRepository`, Ktor, сериализации DTO, REST/WS, bearer-сессий, reconnect и обработки сетевых конфликтов. Будущий default сервера — `http://127.0.0.1:8090`; сейчас адрес не используется. Автоматического переключения с реального сервера на fake нет.
5. Контрактные JSON-fixtures, серверный таймер, идемпотентность и совместная интеграция с Java этим клиентом ещё не проверялись. Успешные тесты backend в его документации не являются тестами Kotlin-клиента.
6. Полный аудит доступности и будущих экранов остаётся в плане. Используется системная рамка Windows; упаковка `.msi`/`.exe`, установка и подпись ещё не выполнены. Bash-команды README не проверялись на Linux/macOS.

## Коммит, push и PR

После просмотра результата выполнить в PowerShell по очереди. Если команда завершилась ошибкой, следующую не выполнять:

```powershell
Set-Location "C:\Users\user\Desktop\focusDuo"
git add -- desktop
git diff --cached --stat
git commit -m "feat(desktop): add demo room and task management"
git push -u origin feat/desktop-mvp
```

Перед коммитом убедиться по списку staged-файлов, что включены только нужные desktop-изменения. Push отправляет рабочую ветку, без слияния в `main`. [Заголовок и описание PR этапа 2](PR_STAGE_2.md).
